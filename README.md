# zod-1c

Декларативная валидация данных для 1С:Предприятие 8.3 в стиле библиотеки Zod.
Схемы описываются fluent-цепочкой, результат проверки содержит данные и
структурированный список ошибок с путями до каждого невалидного поля.

Библиотека не требует БСП, XDTO, внешних компонент и дополнительных
зависимостей. Используется самостоятельно или совместно с библиотекой
`swagger-1c` для рантайм-валидации запросов по описанию OpenAPI.

## Статус

Бета. API стабилен, но возможны уточнения до релиза 1.0.0.

## Требования

- Платформа 1С:Предприятие 8.3.23 и выше (используются регулярные выражения).

## Установка

### Вариант 1: расширение (рекомендуется)

Скачайте последний релиз `zod-1c.cfe` и установите через Конфигуратор:
Конфигурация - Расширения конфигурации - Добавить из файла.

### Вариант 2: копирование исходников

Скопируйте в вашу конфигурацию или расширение:

- общий модуль `Zod` (Сервер, Вызов сервера);
- обработка `Zod_Схема` (модуль объекта);
- обработка `Zod_Трансформер_Телефон` (модуль объекта, опционально);
- обработка `Zod_Трансформер_ПустоеВНеопределено` (модуль объекта, опционально).

## Быстрый старт

```bsl
Схема = Zod.СтрогийОбъект()
    .Поле("clientId", Zod.Строки().Непустая().МаксДлина(50))
    .Поле("email",    Zod.Email())
    .Поле("amount",   Zod.ПриведенноеЧисло().Положительное())
    .Поле("comment",  Zod.Строки().МаксДлина(200).Необязательное());

Результат = Схема.Проверить(Данные);

Если Не Результат.Успех Тогда
    // Результат.Ошибки - массив структур {Путь, Сообщение}
    Возврат ОтветОшибкиВалидации(422, Результат.Ошибки);
КонецЕсли;

// Результат.Данные - проверенная и приведённая Структура
ОбработатьЗаказ(Результат.Данные);
```

## Результат проверки

```bsl
Результат = Схема.Проверить(Значение);

Результат.Успех     // Булево
Результат.Данные    // Проверенное и приведённое значение или Неопределено
Результат.Ошибки    // Массив из Структура("Путь, Сообщение")
```

Для проверки с выбросом исключения при ошибке:

```bsl
Данные = Схема.ПроверитьИлиВыбросить(Значение);
```

## API Reference

### Примитивы

| Фабрика | Возвращает | Пример |
|---|---|---|
| `Zod.Строки()` | Строка | `Zod.Строки().Непустая()` |
| `Zod.Числа()` | Число | `Zod.Числа().Целое()` |
| `Zod.Булевы()` | Булево | `Zod.Булевы()` |
| `Zod.Даты()` | Дата | `Zod.Даты()` |
| `Zod.Любое()` | Любое значение | `Zod.Любое()` |
| `Zod.Литерал(Значение)` | Литерал | `Zod.Литерал("pickup")` |

Имена в множественном числе выбраны намеренно: `Строка`, `Число`,
`Булево`, `Дата`, `Массив` зарезервированы платформой как функции
преобразования типа.

### Объекты

| Фабрика | Возвращает | Неизвестные ключи |
|---|---|---|
| `Zod.Объект()` | Структура или Соответствие | Отбрасываются |
| `Zod.СтрогийОбъект()` | Структура или Соответствие | Ошибка |
| `Zod.СвободныйОбъект()` | Структура или Соответствие | Сохраняются |
| `Zod.Запись(СхемаКлюча, СхемаЗначения)` | Соответствие | Проверяются все ключи |

```bsl
Схема = Zod.Объект()
    .Поле("name", Zod.Строки().Непустая())
    .Поле("age",  Zod.Числа().Целое().МинЗначение(0));

СхемаЗаписи = Zod.Запись(Zod.Строки(), Zod.Числа().МинЗначение(0));
// Принимает {"M10": 100, "M12": 50} -> Соответствие
```

### Манипуляции с полями объекта

Для производных DTO (создание, PATCH, публичный ответ) используются
иммутабельные методы, аналоги `pick` / `omit` / `partial` / `required`
из Zod 4.

| Метод | Описание |
|---|---|
| `.Выбрать(Имена)` | Оставить только перечисленные поля (`pick`) |
| `.Исключить(Имена)` | Убрать перечисленные поля (`omit`) |
| `.СделатьНеобязательными([Имена])` | Сделать поля необязательными (`partial`) |
| `.СделатьОбязательными([Имена])` | Сделать поля обязательными (`required`) |

`Имена` - массив имён полей или одна строка. Без аргумента
`.СделатьНеобязательными()` / `.СделатьОбязательными()` обрабатывают
все поля схемы. Доступны только для схем типа `Объект`. Возвращают
**новую** схему, не изменяя исходную.

```bsl
СхемаПользователя = Zod.СтрогийОбъект()
    .Поле("id",       Zod.Числа().Целое())
    .Поле("Имя",      Zod.Строки().Непустая())
    .Поле("Отчество", Zod.Строки())
    .Поле("Возраст",  Zod.Числа().Целое().МинЗначение(0));

// DTO для создания - без id
СхемаСоздания = СхемаПользователя.Исключить("id");

// DTO для PATCH - без id, все оставшиеся поля необязательные
СхемаПатча = СхемаПользователя
    .Исключить("id")
    .СделатьНеобязательными();

// DTO для публичного ответа - только два поля
Поля = Новый Массив;
Поля.Добавить("Имя");
Поля.Добавить("Возраст");

СхемаОтвета = СхемаПользователя.Выбрать(Поля);
```

Исходная СхемаПользователя при этом не меняется - все три производные
схемы независимы.

Для получения независимой копии схемы без модификаций используется
`.Клонировать()`:

```bsl
Копия = СхемаПользователя.Клонировать();
Копия.Поле("ДополнительноеПоле", Zod.Строки());
// Исходная схема не содержит "ДополнительноеПоле"
```

#### Значения по умолчанию и обработка ошибок

| Модификатор | Аналог в Zod 4 | Описание |
|---|---|---|
| `.ПоУмолчанию(Значение)` | `.default()` | Подставить значение при `Неопределено` / отсутствии ключа |
| `.Поймать(Значение)` | `.catch()` | Вернуть fallback при любой ошибке валидации |

**`.Поймать()` vs `.ПоУмолчанию()` - разные задачи:**

| Задача | Модификатор |
|---|---|
| Fallback, если ключ отсутствует | `.ПоУмолчанию()` |
| Fallback, если значение `Неопределено` | `.ПоУмолчанию()` |
| Fallback, если значение невалидно | `.Поймать()` |
| Fallback и при отсутствии, и при невалидности | `.ПоУмолчанию(fallback).Поймать(fallback)` |

`.Поймать()` срабатывает только когда значение **есть**, но невалидно.
При отсутствии ключа в объекте с `.Необязательное()` поле просто
пропускается - fallback не применяется. Это совпадает с поведением
`z.optional().catch()` в Zod 4:

```typescript
z.string().optional().catch("fallback").parse(undefined); // → undefined
```

`.ПоУмолчанию()` делает поле необязательным на входе:

```bsl
Схема = Zod.СтрогийОбъект()
    .Поле("Имя",     Zod.Строки().Непустая())
    .Поле("Отчество", Zod.Строки().ПоУмолчанию(""));

Результат = Схема.Проверить(Новый Структура("Имя", "Alice"));
// Результат.Данные.Отчество = "" (подставлено)
// Результат.Данные.Имя = "Alice"
```

Для массивов и структур значение shallow-клонируется - мутации
одного результата не протекают в другой.

`.Поймать()` перехватывает любую ошибку - валидации, приведения
или исключения из пользовательской проверки:

```bsl
Схема = Zod.Числа().Поймать(0);
Схема.Проверить("не число").Данные;   // 0
Схема.Проверить(Неопределено).Данные; // 0 (отсутствие тоже ловится)
Схема.Проверить(42).Данные;           // 42
```

Комбинация `.ПоУмолчанию()` + `.Поймать()`: при отсутствии срабатывает
default, при невалидном значении - fallback.

Фабрики. Если нужно каждый раз получать новое значение (например,
свежий массив), передайте обработку с методом Создать() Экспорт:

```bsl
// Обработка МояФабрика, модуль объекта
Функция Создать() Экспорт
    Возврат Новый Массив;
КонецФункции

// Использование
Zod.Массивы().ПоУмолчанию(Обработки.МояФабрика.Создать());
```

Соглашение: фабрика не должна возвращать Неопределено - это
значение зарезервировано как признак «не фабрика».

### Композиция схем

| Метод | Аналог в Zod 4 | Описание |
|---|---|---|
| `.Расширить(Схема)` | `.extend()` / `.merge()` | Добавить поля другой объектной схемы |
| `.Объединить(Схема)` | `.merge()` | Синоним `.Расширить()` |
| `.Пересечение(Схема)` | `.and()` | Значение должно пройти обе схемы |
| `.Конвейер(Схема)` | `.pipe()` | Результат первой передать во вторую |

#### `.Расширить()` - расширение объектной схемы

```bsl
СхемаБазовая = Zod.Объект()
    .Поле("id", Zod.Числа().Целое());

СхемаАудит = Zod.Объект()
    .Поле("createdAt", Zod.Даты())
    .Поле("updatedAt", Zod.Даты());

СхемаПолная = СхемаБазовая.Расширить(СхемаАудит);
// СхемаПолная: id, createdAt, updatedAt
```

При совпадении имён полей побеждает поле из аргумента. Режим объекта
(Строгий / Свободный / Обычный) берётся от исходной схемы.

#### `.Пересечение()` - пересечение

Для объектных схем результаты мержатся. Для примитивов обе схемы
проверяют одно и то же значение.

```bsl
// Проверка длины строки: и не короче 3, и не длиннее 5
Схема = Zod.Строки().МинДлина(3).Пересечение(Zod.Строки().МаксДлина(5));

// Два объекта с разными полями
Схема = Zod.Объект().Поле("a", Zod.Строки())
    .Пересечение(Zod.Объект().Поле("b", Zod.Числа()));
```

Важно: `.Пересечение()` - это именно пересечение, а не merge. Если обе
схемы строгие (`Zod.СтрогийОбъект()`), то лишнее поле для одной будет
лишним и для другой. Для «мягкого» объединения полей используйте
`.Расширить()`.

#### `.Конвейер()` - pipe

Полезен, когда первая схема трансформирует значение, а вторая
валидирует результат:

```bsl
// Привести строку к числу, затем проверить целочисленность
Схема = Zod.ПриведенноеЧисло().Конвейер(Zod.Числа().Целое());

Схема.Проверить("42").Данные;   // 42
Схема.Проверить("1.5").Успех;   // Ложь (1.5 не целое)

// Цепочка из нескольких схем
Схема = Zod.Любое()
    .Конвейер(Zod.ПриведеннаяСтрока())
    .Конвейер(Zod.Строки().Непустая())
    .Конвейер(Zod.Строки().МинДлина(2));
```

Цепочки `.Пересечение().Пересечение()` и `.Конвейер().Конвейер()` разворачиваются в плоские
списки - это видно через `ПолучитьСхемыПересечения()` и
`ПолучитьСхемыКонвейера()`, а также упрощает отладку.

| Фабрика | Пример |
|---|---|
| `Zod.Массивы()` | `Zod.Массивы().Элемент(Zod.Числа()).МинЭлементов(1)` |
| `Zod.Перечисление(Массив)` | `Zod.Перечисление(Значения)` |
| `Zod.Объединение(Массив)` | `Zod.Объединение(МассивСхем)` |
| `Zod.ДискриминированноеОбъединение(Дискриминатор, Массив)` | `Zod.ДискриминированноеОбъединение("method", МассивСхем)` |

### Литералы и дискриминированные объединения

Для описания объектов с взаимоисключающими полями (типичный паттерн -
`method: "pickup" | "delivery"`) используется
`Zod.ДискриминированноеОбъединение()`. Это аналог `z.discriminatedUnion()`
из Zod 4 и `oneOf` с `discriminator` из OpenAPI.

```bsl
СхемаPickup = Zod.СтрогийОбъект()
    .Поле("method", Zod.Литерал("pickup"))
    .Поле("pickup", Zod.Объект()
        .Поле("address", Zod.Строки().Непустая())
        .Поле("storeId", Zod.Числа().Целое()));

СхемаDelivery = Zod.СтрогийОбъект()
    .Поле("method", Zod.Литерал("delivery"))
    .Поле("delivery", Zod.Объект()
        .Поле("address", Zod.Строки().Непустая())
        .Поле("courierPhone", Zod.Строки().Телефон()));

Схемы = Новый Массив;
Схемы.Добавить(СхемаPickup);
Схемы.Добавить(СхемаDelivery);

СхемаЗаказа = Zod.ДискриминированноеОбъединение("method", Схемы);

// method: "pickup" - валидируется только СхемаPickup
Результат = СхемаЗаказа.Проверить(Новый Структура(
    "method, pickup", "pickup",
    Новый Структура("address, storeId", "ул. Ленина, 1", 42)));
// Результат.Успех = Истина

// method: "unknown" - недопустимое значение дискриминатора
Результат = СхемаЗаказа.Проверить(Новый Структура("method", "unknown"));
```

**Правила:**

- Каждый вариант - объектная схема (`Объект`, `СтрогийОбъект`,
  `СвободныйОбъект`).
- В каждом варианте поле-дискриминатор должно иметь тип
  `Zod.Литерал(<уникальное значение>)`.
- Значения дискриминаторов должны быть уникальны; дубликат - исключение
  при построении схемы.
- `Неопределено` в качестве значения литерала-дискриминатора
  не поддерживается.

**Отличия от обычного `Zod.Объединение()`:**

| Характеристика | `Объединение` | `ДискриминированноеОбъединение` |
|---|---|---|
| Проверяемые варианты | Все по очереди | Ровно один, по дискриминатору |
| Ошибки | «Каша» из всех вариантов | Только из выбранного варианта |
| Производительность | O(n) перебор | O(1) поиск по карте |
| Взаимосвязь полей | Не выражена | Строгая (через `Литерал`) |

```bsl
Zod.Email()     // то же, что Zod.Строки().Email()

Zod.Телефон()   // то же, что Zod.Строки().Телефон()

### Модификаторы чисел

| Метод | Описание |

```

### Обязательность и null

По умолчанию все поля обязательны. Управление обязательностью и
допустимостью значения `Неопределено` (в JSON - `null`) выполняется
двумя модификаторами.

| Модификатор | Ключ может отсутствовать | Значение может быть Неопределено |
|---|---|---|
| (без модификатора) | Нет | Нет |
| `.ДопускаетNull()` | Нет | Да |
| `.Необязательное()` | Да | Да |
| `.ДопускаетNull().Необязательное()` | Да | Да |

`Zod.Строки().Необязательное()` в объекте разрешает и отсутствие ключа,
и значение `Неопределено`. Это соответствует `.nullish()` в Zod
(TypeScript), а не `.optional()`. Для строгой семантики `.optional()`
используйте `.ДопускаетNull()` в комбинации с явной проверкой.

Утилиты для программной проверки:

```bsl
Схема.ДопускаетОтсутствие()   // Истина, если ключ может отсутствовать
Схема.ДопускаетНеопределено() // Истина, если значение может быть Неопределено
```

| Фабрика | Принимает | Возвращает |
|---|---|---|
| `Zod.Справочник("Имя")` | UUID-строку, структуру `{type, id}` или ссылку | `СправочникСсылка.Имя` |
| `Zod.Документ("Имя")` | то же | `ДокументСсылка.Имя` |
| `Zod.ПеречислениеСсылка("Имя")` | то же | `ПеречислениеСсылка.Имя` |
| `Zod.ПланВидовХарактеристик("Имя")` | то же | соответствующая ссылка |
| `Zod.ПланСчетов("Имя")`, `Zod.ПланОбмена("Имя")` | то же | соответствующая ссылка |
| `Zod.БизнесПроцесс("Имя")`, `Zod.Задача("Имя")` | то же | соответствующая ссылка |
| `Zod.ЛюбаяСсылка()` | только структуру `{type, id}` | любая ссылка 1С |
| `Zod.СоставнаяСсылка("Тип1")` | структуру `{type, id}` из списка | ссылка одного из типов |

```bsl
// Один тип - можно короткий UUID
Zod.Справочник("Номенклатура")
    .Проверить("a1b2c3d4-...") // -> СправочникСсылка.Номенклатура

// Составная ссылка - только структура {type, id}
Zod.СоставнаяСсылка("Справочник.Пользователи")
    .ИлиСсылка("Справочник.ВнешниеПользователи")
    .Проверить(Новый Структура("type, id", "Справочник.Пользователи", "..."))
```

Модификатор `.ТолькоСуществующая()` возвращает ошибку, если объект с таким
UUID отсутствует в базе.

### Объекты 1С

| Фабрика | Возвращает |
|---|---|
| `Zod.ОбъектДокумента("Имя")` | `ДокументОбъект.Имя` |
| `Zod.ОбъектСправочника("Имя")` | `СправочникОбъект.Имя` |
| `Zod.ОбъектПланаВидовХарактеристик("Имя")` | соответствующий объект |
| `Zod.ОбъектПланаСчетов("Имя")`, `Zod.ОбъектПланаОбмена("Имя")` | соответствующий объект |
| `Zod.ОбъектБизнесПроцесса("Имя")`, `Zod.ОбъектЗадачи("Имя")` | соответствующий объект |

```bsl
Схема = Zod.ОбъектДокумента("ЗаказКлиента")
    .ЗаполнятьПоУмолчанию()
    .Поле("Контрагент", Zod.Справочник("Контрагенты").ТолькоСуществующая())
    .Поле("СуммаДокумента", Zod.Числа().МинЗначение(0))
    .ТабличнаяЧасть("Товары",
        Zod.СтрогийОбъект()
            .Поле("Номенклатура", Zod.Справочник("Номенклатура"))
            .Поле("Количество", Zod.Числа().Целое().Положительное())
            .Поле("Цена", Zod.ПриведенноеЧисло().Положительное()));

Результат = Схема.Проверить(Данные);
// Результат.Данные - заполненный ДокументОбъект.ЗаказКлиента
```

### Утилиты

```bsl
// Сериализация для JSON-ответа
Zod.СериализоватьСсылку(Ссылка)     // -> {type: "Справочник.X", id: "uuid"}
Zod.СериализоватьОбъект(Документ)   // -> Структура с реквизитами и ТЧ

```

### Параметры URL (query string)

HTTP-сервисы часто принимают данные в query string. В 1С
`Запрос.ПараметрыЗапроса` - это `Соответствие`, где все значения приходят
строками. Для единой валидации с JSON-телом используется адаптер
`Zod.ПроверитьПараметрыЗапроса()`.

```bsl
Функция СписокТоваровGET(Запрос) Экспорт

    СхемаПараметров = Zod.СтрогийОбъект()
        .Поле("page",  Zod.ПриведенноеЧисло().Целое().МинЗначение(1).Необязательное())
        .Поле("limit", Zod.ПриведенноеЧисло().Целое().МаксЗначение(100).Необязательное())
        .Поле("sort",  Zod.Перечисление(МассивСортировок()).Необязательное());

    Результат = Zod.ПроверитьПараметрыЗапроса(Запрос, СхемаПараметров);
    Если Не Результат.Успех Тогда
        Возврат ОтветОшибкиВалидации(400, Результат.Ошибки);
    КонецЕсли;

    Возврат ОтветJSON(200, ПостроитьСписок(Результат.Данные));

КонецФункции
```

Адаптер передаёт `ПараметрыЗапроса` (`Соответствие`) в схему напрямую,
без промежуточной структуры. Ключи сохраняются как есть, включая имена,
невалидные для `Структуры` (`user-id`, `filter.name`). Результат проверки
возвращается в `Результат.Данные` как `Соответствие`.

Для чисел, булевых и дат в query обязательно используйте приведение
(`Zod.ПриведенноеЧисло()`, `Zod.ПриведенноеБулево()`, `Zod.ПриведеннаяДата()`).
Для строк, `Zod.UUID()` и `Zod.Перечисление()` приведение не требуется.

## Кастомные проверки и трансформеры

### Проверки

Проверка - это объект с методом `Проверить(Значение)`, который возвращает
одно из:

- `Истина` - валидно;
- `Ложь` - невалидно, стандартное сообщение;
- `Строка` - невалидно, строка используется как сообщение;
- `Структура("Валидно, Сообщение")` - явный вариант;
- `Неопределено` - проверка не применима, пропускается.

```bsl
// Обработка МояПроверка, модуль объекта
Функция Проверить(Значение) Экспорт
    Если Значение.Количество() > 100 Тогда
        Возврат "Слишком много элементов";
    КонецЕсли;
    Возврат Истина;
КонецФункции

// Использование
Zod.Массивы()
    .Элемент(Zod.Числа())
    .Проверка(Обработки.МояПроверка.Создать())
```

Проверки применяются только в том случае, если базовая валидация прошла
без ошибок.

### Трансформеры

Трансформер - это объект с методом `Преобразовать(Значение)`, который
возвращает новое значение. Применяется до валидации.

```bsl
// Нормализация телефона: "8 (999) 123-45-67" -> "+79991234567"
Zod.Строки()
    .Трансформировать(Обработки.Zod_Трансформер_Телефон.Создать())
    .Телефон()
```

Готовая фабрика:

```bsl
Zod.НормализованныйТелефон()
```

Трансформеры комбинируются:

```bsl
Zod.Строки()
    .Трансформировать(Обработки.Zod_Трансформер_ПустоеВНеопределено.Создать())
    .Трансформировать(Обработки.Zod_Трансформер_Телефон.Создать())
    .Телефон()
```

### Адаптер-трансформер (новый способ)

Если типовых преобразований много (Unix timestamp, статусы,
идентификаторы), заводить отдельную обработку на каждый - громоздко.
Альтернатива - одна обработка-диспетчер с публичными методами
и `Zod.Трансформер()`:

```bsl
// Обработка Zod_Трансформеры (пример в комплекте)
// содержит методы UnixTimestamp, СтатусИзСтроки, ЧислоИзИдентификатора

Схема = Zod.Строки()
    .Трансформировать(Zod.Трансформер(Обработки.Zod_Трансформеры,
        "ЧислоИзИдентификатора"))
    .Конвейер(Zod.Числа().Целое().Положительное());

Схема.Проверить("id-42").Данные; // 42
```

**Сигнатура метода-трансформера:** `(Значение, Параметры)`. Второй
аргумент - то, что передано третьим аргументом в `Zod.Трансформер()`.
Если параметры не нужны - передавайте `Неопределено`, метод сам решит,
использовать ли второй аргумент.

**С параметрами** - например, для выбора единицы измерения timestamp:

```bsl
Zod.Трансформер(Обработки.Zod_Трансформеры, "UnixTimestamp",
    Новый Структура("ЕдиницаИзмерения", "Миллисекунды"))
```

**Менеджер или объект.** Первым аргументом можно передать как менеджер
обработки (`Обработки.Zod_Трансформеры`), так и её экземпляр
(`Обработки.Zod_Трансформеры.Создать()`). Для stateless-методов
предпочтителен менеджер - без накладных расходов на создание объекта.
Для методов с состоянием (кэш, настройки) - экземпляр: он создаётся
один раз при построении схемы и переиспользуется.

**Проверка существования метода.** Не выполняется при построении
схемы, чтобы не вызывать метод с `Неопределено/Неопределено` (могли бы
сработать побочные эффекты). Ошибка «метод не найден» возникает при
первом вызове с понятным контекстом:

```
zod-1c: Трансформер(ОбработкаОбъект.Zod_Трансформеры.Опечатка):
Метод объекта не обнаружен (Опечатка)
```

**Имя метода** валидируется как идентификатор 1С при построении
(защита от инъекций). Недопустимые символы → исключение сразу.

**Старый способ остаётся.** Объект с методом `Преобразовать(Значение)`
по-прежнему работает. Выбор:

| Ситуация | Способ |
|---|---|
| Много однотипных преобразований | `Zod.Трансформер(Модуль, "Метод", Параметры)` |
| Сложный трансформер с полями, кэшем, настройками | Отдельная обработка с `Преобразовать(Значение)` |
| Максимальная скорость (миллионы вызовов) | Старый способ (прямой вызов, без `Выполнить()`) |

**Важно: тип схемы vs тип после трансформации.** Трансформеры в zod-1c
работают как **preprocess**, а не как `.transform()` в Zod 4: они
применяются **до** проверки типа. Поэтому нельзя написать:

```bsl
// ❌ Не сработает: трансформер вернёт число, а тип схемы — Строка
Zod.Строки()
    .Трансформировать(Zod.Трансформер(..., "ЧислоИзИдентификатора"))
```

Трансформер вернёт `42` (число), а `ПроверитьПоТипу` попытается
проверить это как строку — ошибка «Ожидалась строка».

Если трансформер должен **сменить тип** — используйте `Zod.Любое()`
как базу и `.Конвейер()` для проверки результата:

```bsl
// ✅ Правильно: Любое пропускает вход, трансформер меняет тип,
// Конвейер валидирует результат
Zod.Любое()
    .Трансформировать(Zod.Трансформер(..., "ЧислоИзИдентификатора"))
    .Конвейер(Zod.Числа().Целое().Положительное())
```

Если трансформер сохраняет тип (нормализация телефона, обрезка строки,
приведение регистра) — можно использовать типизированную базу:

```bsl
// ✅ Трансформер не меняет тип — Строки остаётся Строки
Zod.Строки()
    .Трансформировать(Обработки.Zod_Трансформер_Телефон.Создать())
    .Телефон()
```

Правило: **тип схемы должен совпадать с типом значения ПОСЛЕ
трансформации**, а не до. Если трансформер меняет тип — база `Любое`.

## Режим fail fast

По умолчанию библиотека собирает **все** ошибки. Для больших массивов
и HTTP-payload это бывает избыточно — особенно когда достаточно одной
ошибки, чтобы вернуть клиенту 422. Включается двумя способами:

**1. На уровне вызова** (аналог `safeParse(data, { abortEarly: true })`
в Zod 4):

```bsl
Результат = Схема.Проверить(Данные,
    Новый Структура("ОстановитьсяНаПервойОшибке", Истина));
```

**2. На уровне схемы** — для переиспользуемых глобальных схем:

```bsl
Схема = Zod.Объект()
    .Поле("Заказы", Zod.Массивы()
        .Элемент(Zod.Объект()
            .Поле("Сумма", Zod.Числа().Положительное()))
        .МаксЭлементов(1000))
    .ОстановитьсяНаПервойОшибке();
```

Эффективный флаг = **ИЛИ** флага вызова и флага схемы. Флаг вызова
не может отключить флаг схемы.

**Семантика:**

| Что | Поведение при fail fast |
|---|---|
| Объект | Все поля проверяются (объект = один элемент) |
| Массив | После первого невалидного элемента — прервать |
| Массив + `.МаксЭлементов()` | При превышении — не обходить элементы вообще |
| Массив + `.МинЭлементов()` | При нарушении — не обходить элементы вообще |
| Запись | После первого невалидного ключа — прервать |
| `.Конвейер()` | При падении этапа — следующие не запускать |
| `.Пересечение()` | При падении схемы — следующие не запускать |
| `.Объединение()` | Флаг **не передаётся** в варианты (изоляция ошибок) |
| `.Поймать()` на поле | Ошибка поглощается, fail fast не срабатывает |
| `.Трансформировать()` | Не влияет: исключение не ошибка валидации |

**Маркер в результате:**

```bsl
Результат.ОстановленНаПервойОшибке // Истина, если флаг был активен и были ошибки
```

Удобно для диагностики и логов: сразу видно, что ошибок могло быть
больше.

**Типичный сценарий — большие массивы:**

```bsl
// Сервис принимает до 10 000 заказов, но 10 000 заказов с одной
// и той же ошибкой «Сумма должна быть положительной» — это мусор
Схема = Zod.Объект()
    .Поле("Заказы", Zod.Массивы()
        .Элемент(Zod.Объект()
            .Поле("Сумма", Zod.Числа().Положительное()))
        .МаксЭлементов(10000))
    .ОстановитьсяНаПервойОшибке();

// Сценарий 1: 11 000 заказов → одна ошибка «Макс. элементов: 10000»,
//             обхода элементов нет — ответ за миллисекунды
// Сценарий 2: 5 000 заказов, первый невалиден → одна ошибка от первого
//             элемента, остальные 4999 не проверяются
```

## Известные ограничения

1. В общих модулях 1С нет переменных модуля. `Zod_Схема` - это обработка,
   поэтому каждая схема является независимым объектом. Кэширование схем
   в общем модуле невозможно; при необходимости кэш организуется на уровне
   вызывающего кода.

2. `.Необязательное()` в zod-1c ведёт себя как `.nullish()` в Zod
   (TypeScript): пропускает и отсутствие ключа, и `Неопределено`. Для
   строгой семантики `.optional()` (только отсутствие) используйте
   `.ДопускаетNull()` в комбинации с явной проверкой.

3. `.Паттерн()` работает как `RegExp.test()` в JavaScript: ищет совпадение
   в любом месте строки. Для проверки полного соответствия используйте
   явные анкоры `^...$`.

4. Приведение числа: `Число("")` в 1С выбрасывает исключение, а не
   возвращает 0. Пустая строка не приводится к числу, валидация выдаёт
   ошибку. Для «мягкой» трактовки используйте трансформер
   `Zod_Трансформер_ПустоеВНеопределено` в комбинации с `.Необязательное()`.

5. Приведение числа в русской локали: `Число("1.5")` даёт `15`, а не `1.5`
   (точка интерпретируется как разделитель разрядов). В английской локали
   поведение противоположное.

6. Имена фабрик выбраны в множественном числе, чтобы не пересекаться с
   функциями платформы: `Строки`, `Числа`, `Булевы`, `Даты`, `Массивы`.
   Аналогично `.МинЗначение()` и `.МаксЗначение()` вместо `.Мин()` и
   `.Макс()`.

7. `Zod.ДискриминированноеОбъединение()` не поддерживает вложенные
   дискриминаторы (когда поле-дискриминатор само находится внутри
   вложенного объекта). Дискриминатор всегда читается с верхнего уровня.

## Совместимость с swagger-1c

Библиотека `swagger-1c` (начиная с версии 2.0.0) использует `zod-1c` для
рантайм-валидации запросов через модуль `Swag_ZodАдаптер`. При этом:

- `swagger-1c` работает без `zod-1c` (генерация спецификации не требует
  валидации);
- `zod-1c` работает без `swagger-1c` (это независимые библиотеки);
- при совместной установке `Swag_ZodАдаптер` автоматически определяет
  наличие `zod-1c` и использует его функции.
