# zod-1c

**Декларативная валидация данных для 1С:Предприятие 8.3+**

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![Platform](https://img.shields.io/badge/1C-8.3.23%2B-green.svg)]()
[![Status](https://img.shields.io/badge/status-beta-yellow.svg)]()

`zod-1c` - библиотека для декларативного описания и валидации данных в стиле [Zod](https://zod.dev) для платформы 1С:Предприятие 8.3. Схемы описываются fluent-цепочкой, а на выходе вы получаете структурированные ошибки с путями до каждого невалидного поля.

Библиотека создана для решения практической боли: **HTTP-сервисы и интеграции требуют десятков ручных проверок `Если ... Тогда`**, которые превращают код в нечитаемую простыню. `zod-1c` заменяет их одной декларативной схемой.

```bsl
Схема = Zod.СтрогийОбъект()
    .Поле("clientId", Zod.Строки().Непустая().МаксДлина(50))
    .Поле("email",    Zod.Email())
    .Поле("amount",   Zod.ПриведенноеЧисло().Положительное())
    .Поле("comment",  Zod.Строки().МаксДлина(200).Необязательное())
    .Поле("items",    Zod.Массивы()
        .МинЭлементов(1)
        .Элемент(
            Zod.СтрогийОбъект()
                .Поле("sku",      Zod.Строки().Непустая())
                .Поле("quantity", Zod.Числа().Целое().Положительное())
        ));

Результат = Схема.Проверить(Данные);

Если Не Результат.Успех Тогда
    // Результат.Ошибки: [{Путь: "items[0].sku", Сообщение: "Строка не может быть пустой"}, ...]
    Возврат ОтветОшибкиВалидации(422, Результат.Ошибки);
КонецЕсли;

// Результат.Данные - проверенная и приведённая Структура
ОбработатьЗаказ(Результат.Данные);
```

##  Зачем

### Было

```bsl
Если Данные = Неопределено
    Или Не Данные.Свойство("clientId") Или Не ЗначениеЗаполнено(Данные.clientId)
    Или Не Данные.Свойство("email") Или Не ЗначениеЗаполнено(Данные.email) Тогда
    Возврат ОшибкаJSON(400, "Поля clientId и email обязательны");
КонецЕсли;

Если ТипЗнч(Данные.amount) <> Тип("Число") Или Данные.amount <= 0 Тогда
    Возврат ОшибкаJSON(400, "Сумма должна быть положительным числом");
КонецЕсли;

Если СтрДлина(Данные.clientId) > 50 Тогда
    Возврат ОшибкаJSON(400, "clientId не должен превышать 50 символов");
КонецЕсли;

// ... и ещё 50 строк такого же
```

### Стало

```bsl
Схема = Zod.СтрогийОбъект()
    .Поле("clientId", Zod.Строки().Непустая().МаксДлина(50))
    .Поле("email",    Zod.Email())
    .Поле("amount",   Zod.Числа().Положительное());

Результат = Схема.Проверить(Данные);
Если Не Результат.Успех Тогда
    Возврат ОтветОшибкиВалидации(422, Результат.Ошибки);
КонецЕсли;
```

**Схема - это источник истины.** Она служит документацией контракта, автоматически отдаёт клиенту структурированные ошибки (с путями до каждого поля) и защищает от «тихих» расхождений.

##  Установка

### Вариант 1: Расширение (рекомендуется)

1. Скачайте последний релиз (`.cfe` файл).
2. В конфигураторе: **Конфигурация → Расширения конфигурации → Добавить из файла**.
3. Подключите расширение к вашей конфигурации.

### Вариант 2: Копирование исходников

1. Склонируйте репозиторий.
2. Скопируйте в вашу конфигурацию/расширение:
   - `ОбщийМодуль.Модуль.Zod` → общий модуль `Zod` (Сервер, Вызов сервера).
   - `Обработка.МодульОбъекта.Zod_Схема` → обработка `Zod_Схема`.
   - `Обработка.МодульОбъекта.Zod_Трансформер_Телефон` → обработка `Zod_Трансформер_Телефон` (опционально).
   - `Обработка.МодульОбъекта.Zod_Трансформер_ПустоеВНеопределено` → обработка `Zod_Трансформер_ПустоеВНеопределено` (опционально).

### Требования

- Платформа **1С:Предприятие 8.3.23** и выше (используются регулярные выражения).
- Не требует БСП и других зависимостей.

##  Быстрый старт

### Пример: HTTP-сервис создания заказа

```bsl
// В модуле HTTP-сервиса
Функция СоздатьЗаказPOST(Запрос) Экспорт

    Попытка
        Данные = ПрочитатьJSONИзТела(Запрос);
    Исключение
        Возврат ОтветОшибки(400, "Некорректный JSON");
    КонецПопытки;

    Схема = Zod.СтрогийОбъект()
        .Поле("customerId", Zod.UUID())
        .Поле("items", Zod.Массивы()
            .МинЭлементов(1)
            .Элемент(
                Zod.СтрогийОбъект()
                    .Поле("productId", Zod.Справочник("Номенклатура"))
                    .Поле("quantity",  Zod.Числа().Целое().Положительное())
            ))
        .Поле("comment", Zod.Строки().МаксДлина(500).Необязательное());

    Результат = Схема.Проверить(Данные);

    Если Не Результат.Успех Тогда
        Возврат ОтветОшибкиВалидации(422, Результат.Ошибки);
    КонецЕсли;

    // Результат.Данные - проверенное Соответствие
    Страница = Результат.Данные.Получить("page");
    // productId - уже СправочникСсылка.Номенклатура
    Заказ = СоздатьЗаказ(Результат.Данные);

    Возврат ОтветJSON(201, Новый Структура(
        "orderId", Zod.СериализоватьСсылку(Заказ.Ссылка)
    ));

КонецФункции
```

**Входной JSON:**
```json
{
  "customerId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "items": [
    {"productId": "00000000-0000-0000-0000-000000000001", "quantity": 2}
  ],
  "comment": "Срочный заказ"
}
```

**Ответ при ошибке:**
```json
{
  "errors": [
    {"Путь": "items[0].quantity", "Сообщение": "Значение должно быть положительным"}
  ]
}
```

##  Основные концепции

### Схема - это объект

Каждая схема - независимый экземпляр обработки `Zod_Схема`. Модификаторы (`.Непустая()`, `.МинЗначение()`, …) возвращают `ЭтотОбъект`, что позволяет строить цепочки.

### Результат проверки

```bsl
Результат = Схема.Проверить(Значение);

Результат.Успех     // Булево
Результат.Данные    // проверенное и приведённое значение (или Неопределено)
Результат.Ошибки    // Массив из Структура("Путь, Сообщение")
```

### Необязательность

По умолчанию все поля **обязательны**. `.Необязательное()` разрешает `Неопределено` (в JSON - `null` или отсутствие ключа).

```bsl
Zod.Строки()                  // Обязательное: Неопределено → ошибка
Zod.Строки().Необязательное() // Необязательное: Неопределено → OK
```

### Режимы объектов

| Фабрика | Поведение с неизвестными ключами |
|---|---|
| `Zod.Объект()` | Отбрасываются |
| `Zod.СтрогийОбъект()` | Ошибка «Неизвестное поле» |
| `Zod.СвободныйОбъект()` | Сохраняются в результате |

### Приведение типов

`Zod.ПриведеннаяСтрока()`, `Zod.ПриведенноеЧисло()`, `Zod.ПриведенноеБулево()`, `Zod.ПриведеннаяДата()` - пытаются привести входное значение к нужному типу до валидации. Удобно для JSON, где числа могут прийти строками.

```bsl
Zod.ПриведенноеЧисло().Проверить("123").Данные // 123 (число)
Zod.ПриведенноеЧисло().Проверить("abc").Успех  // Ложь
```

### Единый синтаксис для JSON и query

Схема `Zod.Объект()` работает одинаково хорошо с двумя источниками данных:

| Источник | Что на входе | Результат.Данные | Обращение к полю |
|---|---|---|---|
| Тело JSON | Структура | Структура | Результат.Данные.поле
| Query string | Соответствие | Соответствие | Результат.Данные.Получить("поле")

**Правило:** для query-параметров **всегда** используйте `Zod.ПриведенноеЧисло()`, `Zod.ПриведенноеБулево()`, `Zod.ПриведеннаяДата()` - в URL всё приходит строками. Для JSON-тела приведение опционально (зависит от того, доверяете ли вы типам клиента).

Почему Соответствие, а не Структура? Ключи query-параметров могут быть невалидными для Структуры (user-id, filter.name, 123). Адаптер сохраняет исходный тип, чтобы схема могла проверить любое имя параметра. Это соответствует принципу «что на входе - то и на выходе».

##  API Reference

### Примитивы

| Фабрика | Возвращает | Пример |
|---|---|---|
| `Zod.Строки()` | `Строка` | `Zod.Строки().Непустая()` |
| `Zod.Числа()` | `Число` | `Zod.Числа().Целое()` |
| `Zod.Булевы()` | `Булево` | `Zod.Булевы()` |
| `Zod.Даты()` | `Дата` | `Zod.Даты()` |
| `Zod.Любое()` | любое значение | `Zod.Любое().Необязательное()` |

> ️ Имена в множественном числе выбраны намеренно - `Строка`, `Число`, `Булево`, `Дата`, `Массив` зарезервированы платформой как функции преобразования типа.

### Объекты

| Фабрика | Возвращает | Неизвестные ключи |
|---|---|---|
| `Zod.Объект()` | `Структура` | Отбрасываются |
| `Zod.СтрогийОбъект()` | `Структура` | Ошибка |
| `Zod.СвободныйОбъект()` | `Структура` | Сохраняются |
| `Zod.Запись(СхемаКлюча, СхемаЗначения)` | `Соответствие` | Все ключи валидируются |

```bsl
// Объект с фиксированными полями
Схема = Zod.Объект()
    .Поле("name", Zod.Строки().Непустая())
    .Поле("age",  Zod.Числа().Целое().МинЗначение(0));

// Словарь с произвольными ключами
Схема = Zod.Запись(Zod.Строки(), Zod.Числа().МинЗначение(0));
// Принимает {"М10": 100, "М12": 50} → Соответствие
```

### Коллекции

| Фабрика | Пример |
|---|---|
| `Zod.Массивы()` | `Zod.Массивы().Элемент(Zod.Числа()).МинЭлементов(1)` |
| `Zod.Перечисление(Массив)` | `Zod.Перечисление(Значения)` |
| `Zod.Объединение(Массив)` | `Zod.Объединение(МассивСхем)` |

### Модификаторы строк

| Метод | Описание |
|---|---|
| `.МинДлина(n)` / `.МаксДлина(n)` | Ограничения длины |
| `.Непустая()` | Запрет пустой строки |
| `.Паттерн(Регекс)` | Проверка регулярным выражением (накопительная) |
| `.Email()`, `.URL()`, `.UUID()` | Встроенные форматы |
| `.IPv4()`, `.IPv6()`, `.ДатаISO()` | Форматы сети и даты |
| `.ХешMD5()`, `.ХешSHA256()` | Хеши |
| `.Телефон()` | Телефон РФ (+7 / 8) |
| `.ИНН()`, `.ИНН10()`, `.ИНН12()` | ИНН с контрольной суммой |
| `.СНИЛС()`, `.ОГРН()`, `.ОГРНИП()` | С контрольной суммой |
| `.КПП()`, `.БИК()`, `.РасчетныйСчет()` | Банковские реквизиты |
| `.ОКТМО()`, `.ОКПО()` | Коды статистики |
| `.Луна()` | Номер карты по алгоритму Луна |
| `.EAN13()`, `.EAN8()`, `.ISBN10()`, `.ISBN13()` | Штрих-коды |

Все строковые форматы доступны и как top-level фабрики:
```bsl
Zod.Email()     // == Zod.Строки().Email()
Zod.ИНН()       // == Zod.Строки().ИНН()
Zod.Телефон()   // == Zod.Строки().Телефон()
```

### Модификаторы чисел

| Метод | Описание |
|---|---|
| `.МинЗначение(n)` / `.МаксЗначение(n)` | Границы |
| `.Целое()` | Только целые числа |
| `.Положительное()` | Строго > 0 |

> ️ `.МинЗначение()` и `.МаксЗначение()` названы так, потому что `Мин` и `Макс` - зарезервированные функции платформы.

### Ссылочные типы 1С

| Фабрика | Принимает | Возвращает |
|---|---|---|
| `Zod.Справочник("Имя")` | UUID-строка, `{type, id}` или ссылку | `СправочникСсылка.Имя` |
| `Zod.Документ("Имя")` | то же | `ДокументСсылка.Имя` |
| `Zod.ПеречислениеСсылка("Имя")` | то же | `ПеречислениеСсылка.Имя` |
| `Zod.ПланВидовХарактеристик("Имя")` | то же | соответствующая ссылка |
| `Zod.ПланСчетов("Имя")`, `Zod.ПланОбмена("Имя")` | то же | соответствующая ссылка |
| `Zod.ЛюбаяСсылка()` | только `{type, id}` | любая ссылка 1С |
| `Zod.СоставнаяСсылка("Тип1")` | `{type, id}` из списка | ссылка одного из указанных типов |

```bsl
// Один тип - можно короткий UUID
Zod.Справочник("Номенклатура")
    .Проверить("a1b2c3d4-...") // → СправочникСсылка.Номенклатура

// Составная ссылка - только {type, id}
Zod.СоставнаяСсылка("Справочник.Пользователи")
    .ИлиСсылка("Справочник.ВнешниеПользователи")
    .Проверить(Новый Структура("type, id", "Справочник.Пользователи", "..."))
```

Модификатор `.ТолькоСуществующая()` - ошибка, если объект не найден в базе.

### Объекты 1С (ДокументОбъект, СправочникОбъект, …)

| Фабрика | Возвращает |
|---|---|
| `Zod.ОбъектДокумента("Имя")` | `ДокументОбъект.Имя` |
| `Zod.ОбъектСправочника("Имя")` | `СправочникОбъект.Имя` |
| `Zod.ОбъектПланаВидовХарактеристик("Имя")` | соответствующий объект |
| `Zod.ОбъектПланаСчетов("Имя")`, `Zod.ОбъектПланаОбмена("Имя")` | соответствующий объект |
| `Zod.ОбъектБизнесПроцесса("Имя")`, `Zod.ОбъектЗадачи("Имя")` | соответствующий объект |


### Утилиты

```bsl
// Сериализация для JSON-ответа
Zod.СериализоватьСсылку(Ссылка)     // → {type: "Справочник.X", id: "uuid"}
Zod.СериализоватьОбъект(Документ)   // → Структура со всеми реквизитами и ТЧ

// Проверка
Zod.ЭтоСсылка1С(Значение)           // → Булево

// Форматирование ошибок
Zod.ПлоскиеОшибки(Ошибки)           // → {formErrors: [...], fieldErrors: {поле: [...]}}
Zod.ДеревоОшибок(Ошибки)            // → вложенная структура, зеркалирующая схему
Zod.КрасивыйТекстОшибок(Ошибки)     // → " items[0].sku: Строка не может быть пустой"

// Генерация шаблонов
Схема.СоздатьПустой()               // → все поля, включая необязательные (Неопределено)
Схема.СоздатьМинимальный()          // → только обязательные поля
```

### Параметры URL (query string)

HTTP-сервисы часто принимают данные не только в теле запроса, но и в query string: `?page=2&limit=20&sort=price_asc`. В 1С `Запрос.ПараметрыЗапроса` - это `Соответствие`, где **все значения приходят строками** (даже числа и булевы). Для единообразия с JSON-валидацией используйте адаптер `Zod.ПроверитьПараметрыЗапроса()` - он превращает `ПараметрыЗапроса` в `Структуру` и передаёт её в обычную схему `Zod.Объект()`.

```bsl
// В модуле HTTP-сервиса
Функция СписокТоваровGET(Запрос) Экспорт

    СхемаПараметров = Zod.СтрогийОбъект()
        .Поле("categoryId", Zod.UUID().Необязательное())
        .Поле("search",     Zod.Строки().МаксДлина(100).Необязательное())
        .Поле("page",       Zod.ПриведенноеЧисло().Целое().МинЗначение(1).Необязательное())
        .Поле("limit",      Zod.ПриведенноеЧисло().Целое().МаксЗначение(100).Необязательное())
        .Поле("sort",       Zod.Перечисление(МассивСортировок()).Необязательное())
        .Поле("inStock",    Zod.ПриведенноеБулево().Необязательное());

    Результат = Zod.ПроверитьПараметрыЗапроса(Запрос, СхемаПараметров);
    Если Не Результат.Успех Тогда
        Возврат ОтветОшибкиВалидации(400, Результат.Ошибки);
    КонецЕсли;

    // Результат.Данные.page - уже число, .inStock - уже Булево
    Возврат ОтветJSON(200, ПостроитьСписок(Результат.Данные));

КонецФункции
```

#### Результат - `Соответствие`, а не `Структура`

Поскольку `Запрос.ПараметрыЗапроса` в 1С - это `Соответствие`, и ключи query-параметров могут содержать символы, недопустимые для имён полей `Структуры` (`?user-id=5`, `?filter.name=test`), адаптер **передаёт `Соответствие` в схему напрямую** и возвращает `Соответствие` в `Результат.Данные`.

Обращение к проверенным значениям - через `.Получить()`:

```bsl
Страница = Результат.Данные.Получить("page");
Поиск    = Результат.Данные.Получить("search");
UserID   = Результат.Данные.Получить("user-id");  // невалидный для Структуры ключ
```

Это позволяет использовать в схемах **точно те же имена**, что приходят в URL:

```bsl
Схема = Zod.СтрогийОбъект()
    .Поле("user-id",    Zod.Строки().Необязательное())
    .Поле("filter.name", Zod.Строки().Необязательное())
    .Поле("page",       Zod.ПриведенноеЧисло().Целое().Необязательное());
```

> ️**Отличие от JSON.** Для JSON-тела (`ПрочитатьJSON`) адаптер не нужен - там `Структура` с фиксированными именами полей, `Результат.Данные.поле` работает напрямую. Для query-параметров - `Результат.Данные.Получить("поле")`.

#### Обязательные модификаторы для query-параметров

Поскольку все значения в URL - строки, для чисел и булевых **обязательно** использовать приведение:

| Тип в схеме | Что приходит из URL | Что делать |
|---|---|---|
| `Zod.Числа()` | `"5"` | Упадёт. Нужно `Zod.ПриведенноеЧисло()` |
| `Zod.Булевы()` | `"true"` | Упадёт. Нужно `Zod.ПриведенноеБулево()` |
| `Zod.Даты()` | `"2024-01-15"` | Упадёт. Нужно `Zod.ПриведеннаяДата()` |
| `Zod.Строки()` | `"текст"` | Работает как есть |
| `Zod.Перечисление(...)` | `"price_asc"` | Работает как есть |
| `Zod.UUID()` | `"a1b2c3d4-..."` | Работает как есть |

#### Множественные значения

Если параметр передан несколько раз (`?tag=a&tag=b&tag=c`), платформа 1С помещает в `ПараметрыЗапроса["tag"]` **массив**. Схема должна это учитывать:

```bsl
.Поле("tag", Zod.Массивы().Элемент(Zod.Строки()).Необязательное())
```

Адаптер передаёт массив как есть - схема валидирует его стандартным образом.

#### Поддержка пустых значений

`?search=` (параметр передан, но пустой) даёт в `ПараметрыЗапроса["search"]` пустую строку `""`. Для строковых полей это **валидное значение** - если поле необязательное, `""` останется в результате. Если нужно трактовать `""` как «отсутствие», используйте трансформер:

```bsl
.Поле("search", Zod.Строки()
    .Необязательное()
    .Трансформировать(Обработки.Zod_Трансформер_ПустоеВНеопределено.Создать()))
```

️ **Особый случай - числовые параметры**: `?page=` даёт в 1С `Число("")` → исключение → приведение не удаётся. Если клиент может присылать пустой параметр, добавьте `.Трансформировать(ПустоеВНеопределено)` до приведения:

```bsl
.Поле("page", Zod.ПриведенноеЧисло()
    .Необязательное()
    .Трансформировать(Обработки.Zod_Трансформер_ПустоеВНеопределено.Создать()))
```

```bsl
Функция Проверить(Значение)              // → {Успех, Данные, Ошибки}
Функция ПроверитьИлиВыбросить(Значение)  // → Данные или исключение с текстом ошибок
```

##  Кастомные проверки и трансформеры

### Проверки (`.Проверка()`)

Проверка - объект с методом `Проверить(Значение)`, возвращающим:
- `Истина` - валидно
- `Ложь` - невалидно (стандартное сообщение)
- `Строка` - невалидно, строка используется как сообщение
- `Структура("Валидно, Сообщение")` - явный вариант
- `Неопределено` - проверка не применима, пропускается

```bsl
// Обработка.МодульОбъекта.МояПроверка
Функция Проверить(Значение) Экспорт
    Если Значение.Количество() > 100 Тогда
        Возврат "Слишком много элементов";
    КонецЕсли;
    Возврат Истина;
КонецФункции

// Использование
Zod.Массивы()
    .Элемент(Zod.Числа())
    .Проверка(Обработки.МояПроверка.Создать())
```

Проверки применяются **только если базовая валидация прошла без ошибок**.

### Трансформеры (`.Трансформировать()`)

Трансформер - объект с методом `Преобразовать(Значение)`, возвращающим новое значение. Применяется **до** валидации.

```bsl
// Нормализация телефона: "8 (999) 123-45-67" → "+79991234567"
Zod.Строки()
    .Трансформировать(Обработки.Zod_Трансформер_Телефон.Создать())
    .Телефон()
```

Или top-level:

```bsl
Zod.НормализованныйТелефон()
```

Трансформеры можно комбинировать:
```bsl
Zod.Строки()
    .Трансформировать(Обработки.Zod_Трансформер_ПустоеВНеопределено.Создать())
    .Трансформировать(Обработки.Zod_Трансформер_Телефон.Создать())
    .Телефон()
```

```bsl
    Результат = Zod.СтрогийОбъект()
```

```bsl
Функция ИнформацияОЗаказеGET(Запрос) Экспорт

    Заказ = НайтиЗаказ(Запрос.QueryString);
```

### Разбор query-параметров с валидацией

```bsl
// GET /products?category=...&page=2&limit=20&sort=price_asc&inStock=true
Функция СписокТоваровGET(Запрос) Экспорт

    Схема = Zod.СтрогийОбъект()
        .Поле("categoryId", Zod.UUID().Необязательное())
        .Поле("search",     Zod.Строки().МаксДлина(100).Необязательное())
        .Поле("page",       Zod.ПриведенноеЧисло().Целое().МинЗначение(1).Необязательное())
        .Поле("limit",      Zod.ПриведенноеЧисло().Целое().МаксЗначение(100).Необязательное())
        .Поле("sort", Zod.Перечисление(ЮТКоллекции.ЗначениеВМассиве(
            "name_asc", "name_desc", "price_asc", "price_desc", "new_first"
        )).Необязательное())
        .Поле("inStock", Zod.ПриведенноеБулево().Необязательное());

    Результат = Zod.ПроверитьПараметрыЗапроса(Запрос, Схема);
    Если Не Результат.Успех Тогда
        Возврат ОтветОшибкиВалидации(400, Результат.Ошибки);
    КонецЕсли;

    // Значения по умолчанию для пагинации
    Страница = ?(Результат.Данные.Свойство("page"), Результат.Данные.page, 1);
    Лимит    = ?(Результат.Данные.Свойство("limit"), Результат.Данные.limit, 20);

    Возврат ОтветJSON(200, ПостроитьСписок(Результат.Данные, Страница, Лимит));

КонецФункции
```

**Ошибки клиенту:**

```json
{
  "errors": [
    {"Путь": "limit", "Сообщение": "Макс. значение: 100"},
    {"Путь": "sort",  "Сообщение": "Недопустимое значение"}
  ]
}
```

**Одна схема - два сценария.** Тот же `Zod.Объект()` используется и для `POST`-тела (JSON), и для `GET`-query (строка). Разница только в наличии `.Приведение()` для чисел/булевых/дат и вызове `Zod.ПроверитьПараметрыЗапроса()` вместо `Схема.Проверить()`.

## ️ Известные ограничения

### 1. Нет предопределённой `ПриСозданииОбъекта`

В отличие от OneScript, в 1С **нет** предопределённой процедуры инициализации объекта. Инициализация `Zod_Схема` выполняется явным вызовом `Инициализировать()` внутри `Zod.СоздатьСхему()`.

**Следствие:** не создавайте `Обработки.Zod_Схема.Создать()` напрямую - только через фабрики `Zod.*()`.

### 2. Пустые строки `""` не равны `Неопределено`

`Zod.Email().Необязательное().Проверить("")` → **ошибка**, потому что `""` - валидное значение типа `Строка`, а не отсутствие. Это соответствует семантике Zod.

Если нужно, чтобы `""` трактовалась как отсутствие:

```bsl
Zod.Email().Необязательное()
    .Трансформировать(Обработки.Zod_Трансформер_ПустоеВНеопределено.Создать())
```

### 3. `.Паттерн()` - частичное совпадение

Регулярные выражения работают как `RegExp.test()` в JavaScript: совпадение ищется в любом месте строки. Для проверки «строка целиком соответствует» используйте явные анкоры:

```bsl
Zod.Строки().Паттерн("^\d+$")  // только цифры
Zod.Строки().Паттерн("\d+")     // где-то есть цифры
```

### 4. `Число("")` - это исключение, а не `0`

Распространённое заблуждение: «в 1С `Число("")` даёт `0`». **Это не так**. `Число("")` выбрасывает исключение «Преобразование значения к типу Число не может быть выполнено», как и `Число("abc")`.

| Выражение | Результат |
|---|---|
| `Число("")` |  Исключение |
| `Число(" ")` |  Исключение |
| `Число("abc")` |  Исключение |
| `Число("0")` | `0` |
| `Число(Ложь)` | `0` |
| `Число(Истина)` | `1` |

**Следствие для `Zod.ПриведенноеЧисло()`:** пустая строка **не приводится** к нулю - она даёт ошибку валидации «Не удалось привести к типу Число». Это корректное поведение: клиент передал не число.

**Если нужна «мягкая» трактовка `""` как `0` или как отсутствие значения** - используйте трансформер:

```bsl
// "" → Неопределено → .Необязательное() пропустит
Zod.ПриведенноеЧисло()
    .Необязательное()
    .Трансформировать(Обработки.Zod_Трансформер_ПустоеВНеопределено.Создать())

// Или собственный трансформер "" → 0
Zod.ПриведенноеЧисло()
    .Трансформировать(Обработки.Zod_Трансформер_ПустаяСтрокаВНоль.Создать())
```

**Аналогично про `Число("1.5")`:** в русской локали точка - разделитель разрядов, поэтому `Число("1.5")` даёт `15`, а не `1.5`. В английской локали - наоборот. Если в схеме ожидаются дробные числа, документируйте формат или нормализуйте строку трансформером.

### 5. `Заполнить(Неопределено)`, а не `Заполнить()`

При использовании `.ЗаполнятьПоУмолчанию()` библиотека вызывает `Заполнить(Неопределено)`. Вызов без параметров в некоторых версиях платформы не срабатывает или падает. Это исправлено внутри `zod-1c`, но если вы расширяете библиотеку - держите в голове.

### 6. Не кэшируйте схемы в модулях HTTP-сервисов

Переменные модуля HTTP-сервиса не сохраняются между вызовами. Если нужен кэш - используйте общий модуль с повторным использованием возвращаемых значений, но **не мутируйте закэшированные схемы**.

### 7. Строки и числа обрезаются платформой молча

Если реквизит документа - `Строка(10)`, а схема объявляет `Zod.Строки()` без `.МаксДлина(10)`, платформа молча обрежет значение до 10 символов. Zod-1C не знает ограничений метаданных. Дублируйте их в схеме (в будущих версиях появится `.ПоМетаданным()`).

### 8. `Строка(ТипЗнч(...))` зависит от локали

Не сравнивайте типы через строки:
```bsl
Строка(ТипЗнч(Объект)) = "ДокументОбъект.X"  //  работает не всегда
ТипЗнч(Объект) = Тип("ДокументОбъект.X")     //  всегда
```

### 9. Результат `ПроверитьПараметрыЗапроса` - `Соответствие`, а не `Структура`

`Запрос.ПараметрыЗапроса` в 1С - это `Соответствие`, где ключи не ограничены правилами идентификаторов. Адаптер `Zod.ПроверитьПараметрыЗапроса()` возвращает `Соответствие` в `Результат.Данные`, чтобы сохранить произвольные имена параметров (`user-id`, `filter.name`, `sort[0]`).

**Обращение к полям - через `.Получить("имя")`, а не через точку.** Если нужна именно `Структура` (например, для передачи в существующий код), и ключи гарантированно валидны:

```bsl
Результат = Zod.ПроверитьПараметрыЗапроса(Запрос, Схема);
Если Результат.Успех Тогда
    СтруктураПараметров = Новый Структура(Результат.Данные);  // сработает, если ключи валидны
КонецЕсли;
```

Если среди ключей есть невалидные для `Структуры` (`user-id`, начинающиеся с цифры) - `Новый Структура(Соответствие)` выбросит исключение. В этом случае используйте `Соответствие` напрямую.
