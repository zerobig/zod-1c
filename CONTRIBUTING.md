# Как участвовать в разработке

## Сообщения об ошибках

Создайте issue в репозитории. Приложите:

- версию платформы 1С:Предприятие;
- версию `zod-1c`;
- минимальный пример схемы и значения, на котором воспроизводится проблема;
- ожидаемое и фактическое поведение.

## Предложения по улучшению

Перед созданием issue с предложением проверьте [BACKLOG.md](BACKLOG.md) -
возможно, идея уже зафиксирована. Если нет, создайте issue с описанием
сценария использования и предлагаемого поведения.

## Pull request

1. Форкните репозиторий.
2. Создайте ветку от `main`.
3. Внесите изменения. По возможности добавьте тесты.
4. Убедитесь, что все тесты проходят.
5. Создайте pull request с описанием изменений и ссылкой на issue.

Для изменений, затрагивающих API библиотеки, сначала обсудите предложение
в issue.

## Структура репозитория

- `zod-1c` - основное расширение (общий модуль `Zod`, обработка `Zod_Схема`,
  вспомогательные обработки `Zod_Трансформер_*`).
- `BACKLOG.md` - идеи и задачи на будущее.
- `CHANGELOG.md` - история изменений.

## Стиль кода

- Язык комментариев - русский.
- Публичные функции и процедуры - с комментарием в формате, принятом
  в 1С (описание параметров и возвращаемого значения).
- Имена фабрик используют множественное число (`Строки`, `Числа`, `Булевы`,
  `Даты`, `Массивы`), чтобы не конфликтовать с функциями платформы.
- Модификаторы чисел называются `.МинЗначение()` и `.МаксЗначение()`,
  потому что `Мин` и `Макс` зарезервированы платформой.
- Методы-модификаторы возвращают `ЭтотОбъект` для поддержки fluent-цепочек.

## Тестирование

Тесты используют YaxUnit. Установите `zod-1c` и YaxUnit, запустите
все тесты через стандартный интерфейс YaxUnit.

Для изменений, затрагивающих `Swag_ZodАдаптер` в `swagger-1c`, проверьте
совместимость версий - изменения семантики в `zod-1c` (например, поведение
`.Необязательное()`) должны быть синхронизированы с адаптером.
