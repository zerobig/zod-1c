## Валидация и бизнес-правила

- Кросс-полевые проверки: `.ПроверкаОбъекта()` на уровне объекта, когда
  правило зависит от нескольких полей. Примеры: совпадение `password`
  и `confirmPassword`, `startDate <= endDate`, сумма позиций равна
  `total`, условная обязательность поля в зависимости от значения
  другого поля.
- Метод `.Проверка()` без объекта проверки, с указанием встроенной функции
  по имени. Обсуждалось как альтернатива объектам-проверкам, но было решено
  оставить только объектный паттерн (см. CONTRIBUTING).
- Предикаты для российских реквизитов, которых нет в текущем релизе:
  ПаспортРФ, КБК, БанковскийСчет (с проверкой по БИК), Водительское
  удостоверение, ПолисОМС, ОКВЭД, Кадастровый номер.

## Трансформеры

- `НормализацияEmail`: `СокрЛП` + `НРег`.
- `ОбрезкаПробелов`: `СокрЛП`.
- `СхлопываниеПробелов`: замена `\s+` на один пробел.
- `Округление(Знаков)`: `Окр(Значение, Знаков, РежимОкругления)`.
- `ОграничениеДиапазона(Мин, Макс)`: «зажать» значение вместо ошибки.
- `СтрокаВJSON` и `JSONВСтроку`: для полей `payload`, `metadata`.
- `МассивВСтроку(Разделитель)` и `СтрокаВМассив(Разделитель)`.
- `ПроцентВДолю`: деление на 100.
- `НачалоДня` и `КонецДня` для полей дат.

## Работа со значениями

- Метод `.СоздатьПример()` - генерация валидных значений, проходящих все
  проверки (включая контрольные суммы ИНН, СНИЛС, ОГРН). Полезно для
  документации API.
- Метод `.СтрогоНеобязательное()` - строгая семантика `.optional()` в Zod
  (только отсутствие ключа, без разрешения `Неопределено`).
- Метод `.Заморозить()` - иммутабельность схем с защитой через
  `ФиксированнаяСтруктура`.

## Интеграция

- Генерация `zod-1c`-схем из спецификации OpenAPI (обратный адаптер).
  Используется в `swagger-1c` для клиентов, получающих `swagger.json`
  из внешней системы.
- Экспорт `zod-1c`-схем в JSON Schema (для документации).
- Кэширование схем через общий модуль с повторным использованием
  возвращаемых значений на время сеанса (готовый рецепт для README).
